# Synthea Healthcare Analytics

A healthcare data warehousing and analytics project that transforms synthetic Electronic Health Record (EHR) data into validated, analytics-ready datasets using SQL Server and Power BI.

This project demonstrates an end-to-end healthcare analytics workflow, from source data profiling and data quality assessment to dimensional modeling, data warehouse development, and business intelligence reporting.

The project is designed to demonstrate practical skills in healthcare data analytics, SQL development, data warehousing, and clinical and operational reporting.

---

## 📋 Project Overview

Healthcare organizations generate data across patient demographics, clinical encounters, diagnoses, medications, procedures, and financial transactions. Transforming these records into reliable information requires careful data validation, structured data modeling, and clearly defined analytical metrics.

This project uses synthetic EHR data generated by Synthea to develop a healthcare analytics solution for a hypothetical primary care clinic.

The project involves:

1. **Data Architecture:** Designing a Bronze, Silver, and Gold data architecture using the Medallion Architecture pattern.
2. **Data Profiling & EDA:** Exploring source data, assessing completeness, identifying anomalies, and understanding relationships before transformation.
3. **Data Transformation:** Importing and preparing healthcare CSV files using SQL Server.
4. **Data Quality & Validation:** Identifying missing values, duplicate identifiers, invalid dates, orphan records, and inconsistencies across data layers.
5. **Data Modeling:** Developing fact and dimension tables using a star schema for analytical reporting.
6. **Healthcare Analytics:** Defining meaningful clinical and operational metrics using SQL and DAX.
7. **Business Intelligence:** Developing Power BI dashboards to communicate patient population characteristics, encounter activity, and recorded disease burden.

## 🏥 Project Scenario

A hypothetical primary care clinic wants to understand its patient population, recorded clinical activity, and disease burden through a centralized analytical data model.

The clinic requires a reporting solution that can answer questions such as:

- How many unique patients have recorded encounters?
- How does encounter volume change over time?
- Which encounter types account for the greatest recorded activity?
- Which conditions are most frequently recorded?
- How does the patient population vary by age and gender?
- Which data quality issues could affect the reliability of clinical reports?

The analytical solution will use Synthea synthetic EHR data to demonstrate the data engineering and reporting processes required to answer these questions.

**Important:** Synthea data is synthetic. The project demonstrates analytics workflows and does not represent the actual performance, disease prevalence, or clinical outcomes of a real healthcare organization.

## 🚀 Project Requirements

### 1. Data Warehousing — Healthcare Data Engineering

#### Objective

Develop a SQL Server data warehouse that integrates synthetic EHR datasets into a structured, validated, and analytics-ready data model.

#### Data Sources

The initial project focuses on three CSV files:

- `patients.csv` — patient demographic information.
- `encounters.csv` — recorded healthcare encounters.
- `conditions.csv` — recorded patient conditions and diagnoses.

Additional datasets may be incorporated after the core data model has been validated:

- `procedures.csv`
- `medications.csv`
- `observations.csv`
- `providers.csv`
- `organizations.csv`

Other available datasets, including claims, payer information, allergies, and immunizations, may be considered in subsequent project extensions.

#### Data Quality

Assess and document data quality issues, including:

- Missing identifiers and demographic values.
- Duplicate source identifiers.
- Invalid or inconsistent dates.
- Unexpected categories and values.
- Orphan records and broken relationships.
- Record-count differences across transformation layers.

Data issues will be investigated and documented before decisions are made about correction, exclusion, or retention.

#### Data Integration

Transform the selected source datasets into a consistent analytical model while preserving traceability to the source records.

#### Data Modeling

Develop fact and dimension tables optimized for analytical queries and Power BI reporting.

#### Scope

The initial implementation uses manually executed SQL scripts. Automated ETL orchestration, advanced healthcare interoperability, and production deployment are outside the current project scope.

#### Documentation

Provide documentation covering source data, transformation logic, quality checks, data architecture, dimensional modeling, KPI definitions, and known limitations.

## 🏗️ Data Warehouse Architecture

The project follows a Medallion Architecture consisting of Bronze, Silver, and Gold layers.

### Architecture Overview

```

### Bronze Layer — Raw Data

The Bronze layer stores imported source data in SQL Server.

Responsibilities:

- Import the selected Synthea CSV files.
- Preserve source values as closely as practical.
- Record initial row counts and import issues.
- Perform source-level data quality checks.
- Establish a baseline for subsequent reconciliation.

Schema: `raw`

### Silver Layer — Cleaned and Standardized Data

The Silver layer prepares source data for analytical modeling.

Responsibilities:

- Standardize column names and data types.
- Handle whitespace and category inconsistencies where appropriate.
- Validate identifiers and date fields.
- Identify duplicate and orphan records.
- Document transformation rules and quality exceptions.
- Reconcile Silver records against Bronze.

Schema: `staging`

### Gold Layer — Analytics-Ready Data

The Gold layer contains business-ready datasets designed for reporting.

Responsibilities:

- Define fact-table grain.
- Create dimension and fact tables.
- Implement surrogate keys and analytical relationships.
- Build a star schema for Power BI.
- Validate aggregations and referential integrity.
- Provide reusable analytical datasets.

Schema: `warehouse`

### Power BI — Semantic Model and Reporting

Power BI connects to the Gold layer to deliver interactive healthcare analytics.

Responsibilities:

- Configure dimension-to-fact relationships.
- Create DAX measures for clinical and operational metrics.
- Implement date-based analysis and report filters.
- Build dashboard pages for patient populations and clinic activity.
- Validate reported metrics against independent SQL results.

## ✅ Data Quality & Validation Strategy

Data quality will be assessed throughout the analytical workflow rather than only after the final dashboard has been built.

The validation process includes:

1. Source profiling before import.
2. Row-count and schema reconciliation after Bronze ingestion.
3. Data-type and transformation validation in Silver.
4. Key, relationship, and grain validation in Gold.
5. Independent SQL validation of Power BI measures.

Quality checks will be documented with the number of records tested, the number of exceptions, the relevant validation rule, and the action taken.

Missing values or incomplete dates will not automatically be treated as errors when they are valid for the field's meaning.
